Rust で書かれた mruby 互換 VM の比較 · 2026-10-15 時点

mruby/edge と SabiRuby

どちらも mruby のバイトコードを Rust で実行する VM です。mruby/edge は WebAssembly のエッジ環境やブラウザで小さく動かすことを目的にしています。SabiRuby は、本家 mruby の挙動に合わせ、本家のテストを通すことを目的にしています。目的が違うので、同じ観点でも目指すところが違います。この表は、どちらが優れているかを決めるものではありません。

各行の点線の下は、2026-09-11 に作った前回の表からの変化です。「新しい観点」は今回足した行です。確かめられなかったことは「未確認」、測っていないことは「未測定」と書いています。

前回（2026-09-11）からの主な変化

mruby/edge（84 コミット）

  1. 対象が mruby 4.0（RITE0400）になった。3.x のバイトコードは読まない。
  2. 命令の実装が 119 命令中 109 になった。
  3. break、ブロック内の return、ensure、catch ハンドラ、定数のスコープ、特異クラス、クラス変数の修正が続いた。
  4. DBG セクションの行番号と Exception#backtrace が入った。
  5. 本家 test/t の 48 ファイルを取り込み、互換レポートを公開するようになった。
  6. コンパイラが mec-mrbc-sys（mruby 3.3）から mruby-compiler2-sys 0.5.0 に替わった。
  7. GC の方式（Rc）、Fiber が無いこと、prelude の構成は変わらない。

SabiRuby（0.7.0 まで）

  1. 基準を 4.1.0-rc2 に上げた。本家テストは gem を含めて 2508 件中 2344 件が通る。
  2. 本家コンパイラを別の crate（sabiruby-compiler）として同梱した。crates.io に 5 crate を公開した。
  3. gem が 11 から 36 に増えた。ほかに regexp、mruby-task、eval／Binding／require、マクロ、serde が入った。
  4. 本家比の遅さは、27 ベンチの合計時間で 2.57 倍になった。
  5. ブラウザ（playground）と Bevy（rubevy、wasm を含む）で実際に動くようになった。

目的と成り立ち

目的

mruby/edge

WebAssembly 向けの mruby 互換 VM。ブラウザ、エッジ、組込み、Rust への埋め込みに使う。上流 mruby との挙動の互換を目指すと明記している。

README "Use Cases"、mrubyedge/src/lib.rs
SabiRuby

本の記述を実装で検証する。副産物として、Bevy 向けのつなぎこみ（rubevy）と、ブラウザで動く playground がある。

README 冒頭
変化mruby/edge が「上流 mruby との挙動の互換」を明記した。

対象の mruby バージョン

mruby/edge

mruby 4.0（RITE0400）。ヘッダが 04 でないバイトコードは読まないので、3.x の .mrb は再コンパイルが要る。本家テストは master 891d1d9（2026-10-12）から取り込んでいる。

mrubyedge/COVERAGE.md "Bytecode"、3e4006d
SabiRuby

mruby 4.1 が目標。検証の基準は 4.1.0-rc2。

README 冒頭
変化mruby/edge が 3.2/3.3 系（RITE0300）から 4.0 に移った。SabiRuby は 4.1.0-rc から 4.1.0-rc2 へ。

VM の系譜

mruby/edge

mruby/c 1.2 の vm.c を Rust に写したところから始まった（LICENSE.mrubyc を同梱）。2026-09 以降は、本家 vm.c に合わせた修正も入っている（例: catch ハンドラを catch_handler_find と同じく内側から探す）。

3e4006d のコミットメッセージ
SabiRuby

本家 src/vm.c の仕様の側（レジスタの重ね方、callinfo、catch ハンドラ表、環境、Fiber の状態遷移）を写した。Boxing、setjmp/longjmp、三色 GC、アリーナは別の仕組みに置き換えた。

src/lib.rs 冒頭
変化mruby/edge に本家 vm.c を参照する修正が入った。系譜そのものは変わらない。

同梱のコンパイラ

mruby/edge

mruby-compiler2-sys 0.5.0。mruby 4.0 系の Prism ベースのコンパイラを crate にしたものと読めるが、中身は未確認。VM 本体ではテスト用の依存、CLI では通常の依存。

mrubyedge/Cargo.toml、b02e1d7
SabiRuby

sabiruby-compiler 0.4.0。4.1.0-rc2 の mruby-compiler（Prism と mruby のコード生成）を C のままビルドしている。出力は本家 mrbc とバイト単位で一致する。VM の crate はこれに依存しない。

docs/design/compiler.md
変化mruby/edge は mec-mrbc-sys 3.3.1 を外した。SabiRuby は、前回の「コンパイラを同梱しない」から、別の crate として同梱する形に変わった。

実行のしくみ

命令

mruby/edge

119 命令中 109 を実装。未実装は GETSV SETSV ARGARY ASET INTERN DEBUG ERR EXT1 EXT2 EXT3 の 10 命令で、これに当たると unimplemented! で panic する。4.0 で増えた 13 命令は実装済み。

mrubyedge/src/yamrb/optable.rs、mrubyedge/src/rite/insn.rs
SabiRuby

119 命令すべてを実装（EXT1〜EXT3 を含む）。本家テストで実際に実行された命令は 107/119。

docs/verification/mrbtest.md 末尾
変化mruby/edge は 106 中 89（3.2 の命令表）から、119 中 109（4.0 の命令表）になった。ARYPUSH ARYSPLAT HASHADD HASHCAT GETCV SETCV SETMCNST が入った。

値の表現

mruby/edge

enum RValue（Integer(i64)、Float(f64)、Array(RefCell<Vec<Rc<RObject>>>) など）と Rc。Boxing はしない。

mrubyedge/src/yamrb/value.rs
SabiRuby

16 バイトの Value enum（即値とヒープのオブジェクト ID）。8 バイト化は value.rs の中だけで試せる形にしてあり、まだ保留している。

docs/design/performance.md

例外と大域脱出

mruby/edge

Result<_, Error>。Error に Break、BlockReturn、UnwindJump があり、制御の流れも Result で運ぶ。2026-09〜10 に、ensure の中の例外、重なった catch ハンドラ、ブロックからの return の行き先を修正した。Exception#backtrace と行番号も入った。

mrubyedge/src/error.rs、tests/return_unwind.rs
SabiRuby

Result と巻き戻しのループ（longjmp は使わない）。rescue、ensure、非局所脱出、RBreak 相当まで本家どおり。$! は未対応。

docs/design/exceptions.md
変化mruby/edge で、前回の課題だった break、ブロック内の return、ensure が大きく進み、backtrace が入った。

Fiber とタスク

mruby/edge

無い（ソースに Fiber の語が無い）。

SabiRuby

ある。本家と同じ 6 つの状態を持ち、ホストとの境界での制約も本家に合わせた。加えて mruby-task（Task、Task::Queue、優先度つきスケジューラ）もある。

docs/design/fibers.md、wait-anywhere.md
変化mruby/edge は、前回の「未確認」を「無い」と確かめた。SabiRuby には mruby-task と、ブロックの中での待ちが加わった。

GC

mruby/edge

Rc の参照カウント。マーク＆スイープは無い。env → proc → env の循環を return の時点で切る修正が入った。ほかの循環が漏れるかどうかは未確認。

e874a50
SabiRuby

止めて回収する、移動しないマーク＆スイープ。フリーリストを使う。ネイティブの実行中は回収しない。ストレスモードがある。

docs/design/gc.md
変化mruby/edge は方式はそのままで、循環の 1 つを塞いだ。

実行の中断

mruby/edge

flag_preemption で命令の境目で中断できる。insn-limit feature もある。future-vm（2026-04）の試作のその後は未確認。

mrubyedge/src/yamrb/vm.rs
SabiRuby

Vm::step(n) で、命令数の予算を決めて止められる。mruby-task の Vm::task_run_once で、1 フレームに 1 タスクずつ回せる。

README "Usage"
変化SabiRuby にタスク単位の実行が加わった。

言語機能とライブラリ

パターンマッチ 新しい観点

mruby/edge

MATCHERR は NoMatchingPatternError を上げる。deconstruct／deconstruct_keys は無く、case/in は値のパターンだけ。

mrubyedge/COVERAGE.md
SabiRuby

対応している。本家との差は、ハッシュパターンでキーが対象を書き換えたときに検出しないこと 1 つ。

README "Known deviations"

組込みクラス

mruby/edge

すべて Rust で書いた prelude（mrubyedge/src/yamrb/prelude/）。対応の一覧は COVERAGE.md。Array、Enumerable、Object などのメソッドが増えた。

SabiRuby

本家の mrb_init_core の範囲をネイティブで書いている。本家の mrblib と gem の Ruby 部分は、本家 mrbc でコンパイルしたバイトコードを埋め込む。Integer は 64 ビットを超えると多倍長になる。

変化どちらも中身が増えた。構成は前回と同じ。

gem

mruby/edge

VM の Cargo feature として mruby-regexp（regex crate）、mruby-random、mruby-hash-fnv。別の crate として mrubyedge-math、mrubyedge-time、mruby-serde-json。

SabiRuby

本家 default.gembox のうち POSIX に依存しない 36 gem と mruby-cmath。regexp（regex-automata。後方参照などは RegexpError）、task、sleep、strftime、bigint／rational／complex など。require／load は PicoRuby の形。

docs/design/gems.md
変化SabiRuby は 11 gem から 36 gem に増え、regexp と task も入った。mruby/edge は構成が同じ。

検証

本家テストでの検証

mruby/edge

本家 test/t の 48 ファイルを取り込んだ互換レポートを、master への push ごとに作って公開している（mruby-spec）。b31d334 の時点で、48 ファイル中 9 ファイルが通る。到達した assert ブロックのうち pass は 119、fail は 36、error は 234。このほかに自前のテストが 64 本ある。

mrubyedge/tests/mruby_spec/
SabiRuby

本家の test/t と、移植した gem のテストを走らせている。合わせて 2508 件中 2344 件が通る。test/t（4.1.0-rc2 の 47 ファイル）だけなら 862 件中 845 件で、37 ファイルが全部通る。ファイルごとの下限を決めて、回帰を止めている。

docs/verification/mrbtest.md
変化mruby/edge が本家テストで互換を測り始めた。SabiRuby は前回の 1185/1227 から、gem を含めて 2344/2508 になった。
上の 2 つの数は、そのままでは比べられません。テストを取った本家のコミット（master 891d1d9 と 4.1.0-rc2。refinement.rb は前者にしか無い）、数え方（mruby/edge は到達した assert ブロックだけを、自前の helpers.rb で数える）、gem の有無が違います。
同じテスト（891d1d9 の 48 ファイル）を同じ数え方（mruby/edge の helpers.rb）で両方に走らせると、全部通ったファイルは SabiRuby が 29、mruby/edge が 9、pass した assert ブロックは SabiRuby が 857、mruby/edge が 119 でした（2026-10-16、同じ PC、SabiRuby は開発中のコミット d74ff47）。SabiRuby は mruby 4.1.0-rc2（stable ブランチ）の挙動を実装しているので、891d1d9 のテストのうち master でだけ変わった挙動を確かめるものは落ちます。詳しくは 同じ条件での本家テストの比較 を見てください。

埋め込みと配布

ホストとの連携 API 新しい観点

mruby/edge

mrb_define_cmethod、mrb_funcall、mrb_funcall_with_block など、C の mruby に近い名前の関数。mrbedge wasm は RBS（*.import.rbs／*.export.rbs）から wasm の import／export を作る。

mrubyedge/src/yamrb/helpers.rs、mrubyedge-cli/README.md
SabiRuby

ブラウザで動くか 新しい観点

mruby/edge

動く。公式の Playground がある（中身は未確認）。mrbedge wasm は、WASI を使う wasm と使わない wasm の両方を出せる。

SabiRuby

動く。SabiRuby Playground は VM と本家コンパイラを wasm32-wasip1 で動かす。rubevy も wasm32-unknown-unknown で動く。

docs/design/playground.md

no_std

mruby/edge

README は「no_std に寄せたコア」と書くが、lib.rs に #![no_std] は無く、use std:: が 44 か所ある。no_std のターゲットでのビルドは CI に無い。

SabiRuby

#![no_std] と alloc だけで書く。CI で thumbv7em-none-eabi と wasm32-unknown-unknown をビルドしている。

tools/check_no_std.sh
変化mruby/edge の「no_std 寄り」を、ソースで確かめた結果を書いた。SabiRuby の wasm32 は、ビルドが通るだけの状態から、実際に動く状態になった。

unsafe 新しい観点

mruby/edge

mrubyedge/src に 9 か所。バイナリヘッダの unsafe impl Plain が 5、エンディアン変換の mem::transmute が 2、StaticError の Sync／Send が 1、assume_init_ref が 1。

SabiRuby
