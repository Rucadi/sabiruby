Rust で書かれた mruby 互換 VM の比較 · 2026-10-19 時点

mruby/edge と SabiRuby

どちらも mruby のバイトコードを Rust で実行する VM です。mruby/edge は WebAssembly のエッジ環境やブラウザで小さく動かすことを目的にしています。SabiRuby は、本家 mruby の挙動に合わせ、本家のテストを通すことを目的にしています。目的が違うので、同じ観点でも目指すところが違います。この表は、どちらが優れているかを決めるものではありません。

各行の点線の下は、2026-09-11 に作った前回の表からの変化です。2026-10-19 に、SabiRuby 0.8.0 と mruby/edge の master e30a5e0 に合わせて更新しました。「新しい観点」は今回足した行です。確かめられなかったことは「未確認」、測っていないことは「未測定」と書いています。

前回（2026-09-11）からの主な変化

mruby/edge（93 コミット）

  1. 対象が mruby 4.0（RITE0400）になった。3.x のバイトコードは読まない。
  2. 命令の実装が 119 命令中 109 になった。
  3. break、ブロック内の return、ensure、catch ハンドラ、定数のスコープ、特異クラス、クラス変数の修正が続いた。
  4. DBG セクションの行番号と Exception#backtrace が入った。
  5. 本家 test/t の 48 ファイルを取り込み、互換レポートを公開するようになった。
  6. コンパイラが mec-mrbc-sys（mruby 3.3）から mruby-compiler2-sys 0.5.0 に替わった。
  7. GC の方式（Rc）、Fiber が無いこと、prelude の構成は変わらない。
  8. 2026-10-16: 互換レポートの公開先が別のリポジトリ（mrubyedge/mruby-spec）に移り、レポートに進み具合の棒とファイルの絞り込みが入った。
  9. 2026-10-16: fnv が常に使う依存になった（mruby-hash-fnv は互換のために残った、何もしない feature）。バージョンが 2.1.2 になった。

SabiRuby（0.8.0 まで）

  1. 基準を 4.1.0-rc2 に上げた。
  2. 本家コンパイラを別の crate（sabiruby-compiler）として同梱した。crates.io に 5 crate を公開した。
  3. gem が 11 から 36 に増えた。ほかに regexp、mruby-task、eval／Binding／require、マクロ、serde が入った。
  4. 本家 mruby に対する実行時間の比は、27 ベンチの合計で 2.57 倍（0.7.0）、2.28 倍（0.8.0）。
  5. ブラウザ（playground）と Bevy（rubevy、wasm を含む）で実際に動くようになった。
  6. 0.8.0: 互換の基準を 4.1.0-rc2（stable ブランチ）とし、本家 master（891d1d9）に合わせていた変更を戻した。
  7. 0.8.0: 4.1.0-rc2 との差を洗い出した（両方の VM にあるメソッドの 977,521 回の呼び出しと、502 本の Ruby プログラム）。rc2 に合わせるべき差は直し、rc2 の側が明らかに誤っている差は SabiRuby の答えを残して README "Known deviations" に記録した。
  8. 0.8.0: 27 ベンチの合計時間が、0.7.0 より 8.5% 短くなった。

目的と成り立ち

目的

mruby/edge

WebAssembly 向けの mruby 互換 VM。ブラウザ、エッジ、組込み、Rust への埋め込みに使う。上流 mruby との挙動の互換を目指すと明記している。

README "Use Cases"、mrubyedge/src/lib.rs
SabiRuby

本の記述を実装で検証する。副産物として、Bevy 向けのつなぎこみ（rubevy）と、ブラウザで動く playground がある。

README 冒頭
変化mruby/edge が「上流 mruby との挙動の互換」を明記した。

対象の mruby バージョン

mruby/edge

mruby 4.0（RITE0400）。ヘッダが 04 でないバイトコードは読まないので、3.x の .mrb は再コンパイルが要る。本家テストは master 891d1d9（2026-10-12）から取り込んでいる。

mrubyedge/COVERAGE.md "Bytecode"、3e4006d
SabiRuby

mruby 4.1 が目標。検証の基準は 4.1.0-rc2。

README 冒頭
変化mruby/edge が 3.2/3.3 系（RITE0300）から 4.0 に移った。SabiRuby は 4.1.0-rc から 4.1.0-rc2 へ。

VM の系譜

mruby/edge

mruby/c 1.2 の vm.c を Rust に写したところから始まった（LICENSE.mrubyc を同梱）。2026-09 以降は、本家 vm.c に合わせた修正も入っている（例: catch ハンドラを catch_handler_find と同じく内側から探す）。

3e4006d のコミットメッセージ
SabiRuby

本家 src/vm.c の仕様の側（レジスタの重ね方、callinfo、catch ハンドラ表、環境、Fiber の状態遷移）を写した。Boxing、setjmp/longjmp、三色 GC、アリーナは別の仕組みに置き換えた。

src/lib.rs 冒頭
変化mruby/edge に本家 vm.c を参照する修正が入った。系譜そのものは変わらない。

同梱のコンパイラ

mruby/edge

mruby-compiler2-sys 0.5.0。mruby 4.0 系の Prism ベースのコンパイラを crate にしたものと読めるが、中身は未確認。VM 本体ではテスト用の依存、CLI では通常の依存。

mrubyedge/Cargo.toml、b02e1d7
SabiRuby

sabiruby-compiler 0.5.0。4.1.0-rc2 の mruby-compiler（Prism と mruby のコード生成）を C のままビルドしている。出力は本家 mrbc とバイト単位で一致する。VM の crate はこれに依存しない。

docs/design/compiler.md
変化mruby/edge は mec-mrbc-sys 3.3.1 を外した。SabiRuby は、前回の「コンパイラを同梱しない」から、別の crate として同梱する形に変わった。

実行のしくみ

命令

mruby/edge

119 命令中 109 を実装。未実装は GETSV SETSV ARGARY ASET INTERN DEBUG ERR EXT1 EXT2 EXT3 の 10 命令で、これに当たると unimplemented! で panic する。4.0 で増えた 13 命令は実装済み。

mrubyedge/src/yamrb/optable.rs、mrubyedge/src/rite/insn.rs
SabiRuby

119 命令すべてを実装（EXT1〜EXT3 を含む）。本家テストで実際に実行された命令は 107/119。

docs/verification/mrbtest.md 末尾
変化mruby/edge は 106 中 89（3.2 の命令表）から、119 中 109（4.0 の命令表）になった。ARYPUSH ARYSPLAT HASHADD HASHCAT GETCV SETCV SETMCNST が入った。

値の表現

mruby/edge

enum RValue（Integer(i64)、Float(f64)、Array(RefCell<Vec<Rc<RObject>>>) など）と Rc。Boxing はしない。

mrubyedge/src/yamrb/value.rs
SabiRuby

16 バイトの Value enum（即値とヒープのオブジェクト ID）。8 バイト化は value.rs の中だけで試せる形にしてあり、まだ保留している。

docs/design/performance.md

例外と大域脱出

mruby/edge

Result<_, Error>。Error に Break、BlockReturn、UnwindJump があり、制御の流れも Result で運ぶ。2026-09〜10 に、ensure の中の例外、重なった catch ハンドラ、ブロックからの return の行き先を修正した。Exception#backtrace と行番号も入った。

mrubyedge/src/error.rs、tests/return_unwind.rs
SabiRuby

Result と巻き戻しのループ（longjmp は使わない）。rescue、ensure、非局所脱出、RBreak 相当まで本家どおり。$! は未対応。

docs/design/exceptions.md
変化mruby/edge で、前回の表で挙げた break、ブロック内の return、ensure が大きく進み、backtrace が入った。

Fiber とタスク

mruby/edge

無い（ソースに Fiber の語が無い）。

SabiRuby

ある。本家と同じ 6 つの状態を持ち、ホストとの境界での制約も本家に合わせた。加えて mruby-task（Task、Task::Queue、優先度つきスケジューラ）もある。

docs/design/fibers.md、wait-anywhere.md
変化mruby/edge は、前回の「未確認」を「無い」と確かめた。SabiRuby には mruby-task と、ブロックの中での待ちが加わった。

GC

mruby/edge

Rc の参照カウント。マーク＆スイープは無い。env → proc → env の循環を return の時点で切る修正が入った。ほかの循環が漏れるかどうかは未確認。

e874a50
SabiRuby

止めて回収する、移動しないマーク＆スイープ。フリーリストを使う。ネイティブの実行中は回収しない。ストレスモードがある。

docs/design/gc.md
変化mruby/edge は方式はそのままで、循環の 1 つを塞いだ。

実行の中断

mruby/edge

flag_preemption で命令の境目で中断できる。insn-limit feature もある。future-vm（2026-04）の試作のその後は未確認。

mrubyedge/src/yamrb/vm.rs
SabiRuby

Vm::step(n) で、命令数の予算を決めて止められる。mruby-task の Vm::task_run_once で、1 フレームに 1 タスクずつ回せる。

README "Usage"
変化SabiRuby にタスク単位の実行が加わった。

言語機能とライブラリ

パターンマッチ 新しい観点

mruby/edge

MATCHERR は NoMatchingPatternError を上げる。deconstruct／deconstruct_keys は無く、case/in は値のパターンだけ。

mrubyedge/COVERAGE.md
SabiRuby

対応している。本家との差は、ハッシュパターンでキーが対象を書き換えたときに検出しないこと 1 つ。

README "Known deviations"

組込みクラス

mruby/edge

すべて Rust で書いた prelude（mrubyedge/src/yamrb/prelude/）。対応の一覧は COVERAGE.md。Array、Enumerable、Object などのメソッドが増えた。

SabiRuby

本家の mrb_init_core の範囲をネイティブで書いている。本家の mrblib と gem の Ruby 部分は、本家 mrbc でコンパイルしたバイトコードを埋め込む。Integer は 64 ビットを超えると多倍長になる。

変化どちらも中身が増えた。構成は前回と同じ。

gem

mruby/edge

VM の Cargo feature として mruby-regexp（regex crate）、mruby-random。fnv は 2.1.2 から常に使う依存で、mruby-hash-fnv は何もしない feature として残っている。別の crate として mrubyedge-math、mrubyedge-time、mruby-serde-json。

SabiRuby

本家 default.gembox のうち POSIX に依存しない 36 gem と mruby-cmath。regexp（regex-automata。後方参照などは RegexpError）、task、sleep、strftime、bigint／rational／complex など。require／load は PicoRuby の形。

docs/design/gems.md
変化SabiRuby は 11 gem から 36 gem に増え、regexp と task も入った。mruby/edge は構成が同じで、fnv が feature から常の依存に変わった。

本家テストでの検証

mruby/edge

本家 test/t の 48 ファイルを取り込んだ互換レポートを、master への push ごとに作って公開している（mruby-spec。2026-10-16 から別のリポジトリ mrubyedge/mruby-spec で公開）。数えるのは到達した assert ブロックで、途中で止まったファイルの残りは数えない。このほかに自前のテストが 64 本ある。

mrubyedge/tests/mruby_spec/

docs/verification/mrbtest.md

ホストとの連携 API 新しい観点

mruby/edge

mrb_define_cmethod、mrb_funcall、mrb_funcall_with_block など、C の mruby に近い名前の関数。mrbedge wasm は RBS（*.import.rbs／*.export.rbs）から wasm の import／export を作る。

mrubyedge/src/yamrb/helpers.rs、mrubyedge-cli/README.md
SabiRuby

ブラウザで動くか 新しい観点

mruby/edge

動く。公式の Playground がある（中身は未確認）。mrbedge wasm は、WASI を使う wasm と使わない wasm の両方を出せる。

SabiRuby

動く。SabiRuby Playground は VM と本家コンパイラを wasm32-wasip1 で動かす。rubevy も wasm32-unknown-unknown で動く。

docs/design/playground.md

no_std

mruby/edge

README は「no_std に寄せたコア」と書くが、lib.rs に #![no_std] は無く、use std:: が 45 か所ある。no_std のターゲットでのビルドは CI に無い。

SabiRuby

#![no_std] と alloc だけで書く。CI で thumbv7em-none-eabi と wasm32-unknown-unknown をビルドしている。

tools/check_no_std.sh
変化mruby/edge の「no_std 寄り」を、ソースで確かめた結果を書いた。SabiRuby の wasm32 は、ビルドが通るだけの状態から、実際に動く状態になった。

unsafe 新しい観点

mruby/edge

SabiRuby

VM の crate は 0 か所（作者の方針で禁止）。C との境界である compiler/src/ffi.rs に 7 か所。

規模・サイズ・性能

ソースの行数

mruby/edge

mrubyedge/src の .rs が 13,399 行（2026-04 は 12,049 行）。

SabiRuby

src/ の .rs が 28,936 行。このほかに compiler、cli、macros、serde の crate がある。

変化数え方はどちらも wc -l（空行とコメントを含む）。mruby/edge は約 1 割増えた。SabiRuby は約 9,000 行から約 28,900 行に増えた。

wasm のサイズ 新しい観点

mruby/edge

2026-09-12 と同じ条件（VM だけの wasm32-unknown-unknown、release、lto、codegen-units = 1、panic = "abort"、strip、wasm-opt -Oz（binaryen 132））で、2026-10-19 に測った。2.1.2（既定の features）は 579,166 バイト（gzip で 192,914）。2026-09-12 の 1.1.12 は 562,560 バイト（gzip で 185,343）。

SabiRuby

同じ計測で、0.8.0（既定の features: utf8、regexp）は 2,001,572 バイト（gzip で 707,958）、--no-default-features で 1,226,351 バイト（gzip で 441,957）。2026-09-12 の 0.2.0 は 783,729 バイト（gzip で 281,054）。

docs/design/playground.md、docs/worklog/2026-10-19-edge-compare-0.8.md
変化今回測った。同じ手順と今の toolchain（rustc 1.97.0）で 2026-09-12 のバージョンを建て直すと、1.1.12 は 562,928 バイト、0.2.0 は 785,072 バイトで、記録との差は 0.2% 以内だった。2026-09-13 に記録した gem 入りの SabiRuby の数（1,261,940 バイトなど）は、この手順で建て直しても再現しなかったので、ここでは使わない。

性能

mruby/edge

2026-10-19 に、同じ PC で SabiRuby と同じベンチ（bench/ の 27 本、本家 mrbc 4.1.0-rc2 でコンパイルした .mrb）を走らせた。両方が同じ出力を出した 12 本の合計時間は、mruby/edge が 119.6 秒、SabiRuby が 13.8 秒（比は合計で 8.65 倍、ベンチごとに 2.43〜17.77 倍、中央値 8.79 倍）。mruby/edge は VM だけを既定の features で組み、VM::open と run を呼ぶ小さなコマンドで走らせた（別の crate の mrubyedge-math などは入れていない）。残りの 15 本は比べていない: 13 本は、ベンチが使う定数やメソッド（Math、ARGV、Fiber、GC、putc、print など）がこの組み方に無く、1 本（vm_optimization_bench）は引数の無い puts のところで実行が止まり、1 本（mem_retained）は 120 秒で終わらなかった。criterion のベンチはあるが、公開された数は見つからなかった。

docs/worklog/2026-10-19-edge-compare-0.8.md
SabiRuby

本家 mruby 4.1.0-rc2 に対する実行時間の比は、27 ベンチの合計時間で 2.28 倍（比の中央値は 2.70 倍）。

docs/verification/bench.md "0.8.0 candidate"、bench/results/release-0.8/ref-e7a3381.md
変化SabiRuby の本家比は、2.57 倍（0.7.0、比の中央値 2.85 倍）から 2.28 倍（0.8.0）になった。最初の計測では、算術で 1.8〜3.5 倍、配列で 16 倍だった。2 つの VM どうしは、今回初めて同じベンチで測った（12 本）。測り方は、コアを 1 つに固定して 5 回走らせた最良の時間、2 つの VM の順番を入れ替えて 2 巡（巡の間の差は 1.3% 以内）。

周辺のリポジトリ

  • mruby/edge: mrubyedge-cli（mrbedge run／compile-mrb／wasm）と、公式の Playground。
  • SabiRuby: rubevy（Bevy 0.19 向けの汎用のつなぎこみ。スクリプトを SabiRuby のタスクとして動かし、ECS のコンポーネント、リソース、イベントを Ruby から扱う）と、sabiruby-playground（ブラウザだけで本家コンパイラと VM を動かす静的ページ）。

未確認・未測定

  • 27 本のベンチのうち 15 本での、2 つの VM の性能（上の「性能」の行）。mruby/edge の別の crate（mrubyedge-math など）を入れたときのサイズと性能。
  • mruby-compiler2-sys 0.5.0 の中身（どの mruby のコンパイラか、作者は誰か）。
  • mruby/edge の公式 Playground の中身と、crates.io 上の最新バージョン。
  • mruby/edge の future-vm（Future 化）の試作のその後。
  • mruby/edge で、Rc の循環がほかにも残っているかどうか。

パスに接頭辞が無いものは、それぞれのリポジトリの中のパスです。mruby/edge 側は master e30a5e0、SabiRuby 側は v0.8.0（7f74cd1）のものです。
