# 2026-10-18 rc2 との差の洗い出し（X1・X2、調査だけ）

計画: `../plans/rc2-sweep-plan.md`。基準: SabiRuby main `f009316`（`cargo build --release -p sabiruby-cli`）、
rc2 = Docker `kishima/mruby:4.1.0-rc2-utf8`。VM のコードは変えていない。結果のまとめは
`../verification/rc2-sweep/README.md`。

## 再開のしかた（途中で止まったとき）

道具は `tools/rc2_sweep/`。作業の出力は `target/rc2-sweep/`（git に入れない）。

```
cargo build --release -p sabiruby-cli
python3 tools/rc2_sweep/sweep.py lists              # 両方の VM からメソッドの一覧（Docker）
python3 tools/rc2_sweep/sweep.py cases              # 呼び出しの表とその数（VM は走らせない）
python3 tools/rc2_sweep/sweep.py run --timeout 5    # 全部（--only '受け手の正規表現' で一部だけ）
python3 tools/rc2_sweep/compare.py                  # 分類 → target/rc2-sweep/x1-diffs.tsv と docs の縮めた表
python3 tools/rc2_sweep/programs.py run --timeout 60
python3 tools/rc2_sweep/programs.py compare         # → docs/verification/rc2-sweep/x2-*.tsv
```

`run` は受け手ごとの塊（chunk）を両側で走らせ、`target/rc2-sweep/raw/{ref,sabi}/<受け手>.tsv` に 1 呼び出し 1 行で書く。
途中の塊は消して `--only` でやり直せばよい。

## どの像と比べるか

SabiRuby の既定のビルドは文字列が文字（feature `utf8`）。`kishima/mruby:4.1.0-rc2` は文字列がバイトの像で、
`"あ".size` が 3 になる。X1 の値に `"あ"` があるので、`MRB_UTF8_STRING` で建てた `-utf8` の像を正解にした。
tests/custom だけは `tools/custom.sh` の規則（`# utf8-only:` の印のあるものが utf8 の像、他はバイトの像。
`.rc.out` がそこから来ている）をそのまま使った。

## X1. メソッドの洗い出し

### 一覧

最初は `methods.rb` で `Object.constants` から届くクラスとモジュールを並べ、持ち主ごとの
`instance_methods(false)` などを両方で書き出した。rc2 の一覧に Integer が出なかった — `Fixnum` が
`Integer` の別名で、名前順で先に見つかったため。`v.name != c.to_s` の別名を飛ばして直した。
rc2 には mruby-io・mruby-socket の IO・File・Socket・Errno::*（135 個）があり、SabiRuby には Task・CMath・
LoadError がある。両方にあるのは 66 のクラス・モジュール。

持ち主の一覧は rc2-leftovers9 V1-1 と同じく持ち主の違い（rc2 は `Integer#<`、SabiRuby は `Numeric#<`）まで差に出す。
呼ぶ表にはそれを使わず、受け手ごとに「呼べるメソッド」（`public_methods + protected_methods + private_methods`）を
両方で書き出し（`receivers.rb`）、両方で呼べる名前だけを呼んだ。片方だけで呼べるものは `x1-one-side-callable.tsv`、
持ち主ごとの表は `x1-one-side.tsv` に残した。

### 受け手と引数

受け手は `prelude.rb` の 101 個（クラスごとに空・中身あり・凍結、クラス自身の特異メソッド用に 34 個の `self:X`）。
値は計画の 22 個をその順で。どちらも lambda にして呼び出しのたびに新しく作る（破壊的なメソッドが次に持ち越さない。
引数を書き換えるメソッドもある）。`srand(1)` を毎回呼ぶ（`rand` の答えを比べられるように）。

呼ぶ名前の選び方:
- `self:X` では X の特異クラスが持ち主のものだけ。`Integer.freeze` や `Object.define_method` が後の呼び出しを
  壊すので、Module・Class・Kernel のメソッドは `Module.new`・`Class.new` で呼ぶ。
- Object 以外の受け手では、持ち主が Kernel・BasicObject・Object のものを呼ばない（Object.new で 1 回）。
- 外したもの（`cases.py` の SKIP）: 止まる・外に出る（exit、sleep、loop、gets、system、`` ` ``、open …）、
  ほかのファイルを読む（require、load …）、eval 系（eval、instance_eval、class_eval、module_eval、
  instance_exec …）、結果を読む標準出力に書く（p、puts、print、printf、putc、display、warn …）、ヒープを歩く
  （each_object、count_objects）。実際に外れた組は `x1-left-out.tsv`（31 組）。

### 組み合わせの数と上限

引数の個数は rc2 自身の宣言（`tools/rc2-aspec/rc2-aspec.tsv`、rc2 の VM が個数を検査する MRB_ARGS_*）から
`req + post` 〜 `req + post + opt`（rest なら計画の上限 3 まで）。宣言が要らない数を外れる呼び出しは
`tools/rc2_aspec.sh --compare` で別に比べてあるので（989 / 989 同じ）、ここでは宣言の内側だけを呼ぶ。
値の組: 0・1 個は全部、2 個は 22×22 の全部、3 個は全部だと 10648 なので、どの 2 つの位置にもどの 2 つの値の組が
1 度は出る直交ラテン方格 `(a, b, (a+b) mod 22)` の 484 行にした（数は 2 個と同じ）。
block とキーワード `k: 1`: 宣言にあれば全部の行で、無ければいちばん少ない個数の行でだけ（宣言せずに block を読む
C の関数を拾うため）。

数えると 981,866 呼び出し（受け手とメソッドの組 4,338、86 の受け手。0 個 8,520、1 個 118,118、2 個 510,620、
3 個 344,608）。試しに 6 つの受け手（175,051 呼び出し）を回すと両側とも 12 秒、1 呼び出しは遅くて 0.066 秒。
これなら全部回せるので、組み合わせを削る上限は置かなかった（3 個のラテン方格だけが計画の「全部」からの間引き）。

### 1 呼び出しごとの時間の上限

最初の全体の走行は上限 60 秒で回した。85 の塊は 2〜3 分で終わり、終わった呼び出しの最も遅いものは
0.112 秒だった（約 96 万呼び出し）。残った `(1..)`（終わりの無い Range）の塊は `all?`・`count`・`sum`・
`inject(:+)` などが本当に終わらず、1 つ 60 秒では何時間もかかるので止めた。この塊だけを上限 5 秒でやり直した。
5 秒は終わった呼び出しの最も遅いもの（0.112 秒）の 40 倍以上で、上限に当たったものは遅いのではなく終わらない、
と読める幅。数は `sweep.py run --timeout` で変えられる（既定値は置かず、毎回渡す）。

### 走らせ方で詰まったこと

- **大きな配列の literal**: 1 万要素の `SW_CASES = [...]` は rc2 の codegen が "too big jump offset" で拒む。
  タブ区切りの文字列にして実行時に split した。その文字列も 64KB を超えると "string literal too long"
  （`codegen.c new_lit_str`、RITE の pool の長さが 16 ビット）なので、64KB 以下に切って配列にした。
- **SabiRuby の CLI は出力を最後まで持つ**: `sabiruby` コマンドは VM の出力を終わるまで貯めて出す
  （`cli/src/main.rs`）。途中で止まる呼び出しがあると、その前の結果も全部消える。CLI を変えずに済ませるため、
  SabiRuby 側は `sabiruby edge-spec start.mrb chunk.mrb` で走らせた。edge-spec の `t_print` はその場で書き出す。
  開始位置は `SW_START = n` を書いた小さな `.mrb` で渡す。edge-spec が Object に足す `_spec_event`・`t_print`・
  `_str_match?` は、名前の一覧から取り除いて比べた。
- **block の記録が際限なく伸びる**: `7.step { }` のような終わらない繰り返しで、block に渡ったものの記録が
  メモリを食い尽くす。rc2 は "array size too big"、SabiRuby は確保の失敗で abort（ulimit の下で）と、
  メモリが尽きたときの振る舞いを比べることになる。block を `SW_YIELD_MAX = 9**3` 回で止めた（`SwStop`、
  Exception の直下なので method の `rescue` に取られない）。9 は受け手・引数でいちばん要素の多い `1...10` の
  9 個、3 は引数の上限。これより多く yield するのは 2**70 や Infinity に向かう繰り返しだけ。
- **メモリの上限**: 1 プロセスのアドレス空間を `MemAvailable` の半分を同時に走るプロセスの数で割った値
  （この機械で約 1GB）にした。`--mem` で変えられる。
- **並列の数**: 片側ずつ CPU の 1/4（6）。隣で別の担当が Docker を使っているので半分を残した。`--jobs`。

### 正規化と分類

正規化（`compare.py` の冒頭）: アドレス `0x…` を `0x` に、`object_id`・`__id__` の値を `<id>` に、名前の一覧を返す
メソッド（methods、constants、global_variables など）は並べ替えてから（順は VM のハッシュ表の順）。
`hash` の値は正規化しない（記録した差 k に入れる）。

分類（計画どおり）: v 値・受け手のその後・block に渡ったものが違う / e 例外のクラスが違う（片方だけ例外、
crash、timeout も） / m 例外のクラスが同じで文言だけ違う / k 既に記録した差。k の当て方は `compare.py`
`known()` に 1 規則 1 行で、どの記録に当たるかを返す（README Known deviations、backlog、`design/gems.md`
"Deviations kept"）。例外のクラスも文言も同じで受け手や block の記録が違うものは m ではなく v にした
（最初の版は m に入れていて、Binding の inspect の差が「given の数の差（k）」に見えた）。

原因ごとのまとめは `causes.py`: 最初は自動の鍵（例外ならクラスと値を抜いた文言の組、値ならメソッド）で
まとめ、大きい組から読んで 1 行の再現を両方で確かめ、規則にした。読んで確かめた再現（`scratchpad` の `q.rb`）:

## X2. Ruby のプログラム

本の `data/code/*.rb` 161、tests/custom 60、porting-kit の fixtures 15 と samples 158、本家のテスト 108 ファイル
（`tests/mrbtest/src/`、`tools/mrbtest.sh` がコピーしたもの。バイト列のビルドの組 `gem_ascii_*` を除く）、計 502。
本家のテストは assert を 1 つずつ別のプログラムに切り出す代わりに、1 ファイルを 1 プログラムとして、
`assert_patch.rb` で assert ごとに 1 行（番号、深さ、名前、結果の印、失敗の文言）を書かせて、assert ごとに比べた。
切り出すとファイルの上の方で定義したクラスや helper が無くなり、両方で同じ理由で落ちるだけになるため。
C のテストドライバ（`mruby-test/driver.c`）の `t_print`・`_str_match?`・`Mrbtest::FLOAT_TOLERANCE` は
Ruby で書いて両方に同じものを入れた。C の fixture（vformat、ary_shared、env ほか）はどちらにも無い。

詰まったこと: `codegen.rb` は Regexp の定数を消すテストを持ち、rc2 の `String#gsub` は文字列の pattern でも
Regexp を読むので、assert の行を書く helper（最初は gsub で改行を逃がしていた）が rc2 でだけ落ちて、
残りの assert が全部「片方に無い」になった。helper を each_char で書き直した。

時間の上限 60 秒: 終わったもので最も遅いのは 1.33 秒（SabiRuby の `gem_regexp_syntax.rb`）。上限に当たったのは
`test_NOP_empty_loop.rb`（本と kit の 2 つ、両方で、わざと終わらないプログラム）だけ。

### 原因ごとのまとめ（2 回目、セッションが切れた後の続き）

前の担当は `causes.py` の規則を 40 個ほど作ったところで止まっていた。そのときの表は差 68,583 呼び出しのうち
`auto:`（自動の鍵のまま）が 146 組・6,543 呼び出し（9.5%）。再走行はせず、`target/rc2-sweep/raw/` の結果に
`compare.py` を回し直すだけで進めた（1 回 5 秒）。

最初に、`compare.py` の生成物（`x1-counts.md` など）が `compare.py` 自身より古かったので回し直した。
比べた数が 973,220 から 977,521 に増え、答えの無いものが 8,646 から 4,345 に減った。`(1..)` の塊を 5 秒で
やり直した走行（`run-endless.log`）が、前のセッションの終わりまで raw を書き足していたため。この塊は
16,388 呼び出しのうち 4,345 が未走行のまま（`zip`・`reduce` が 1,983 ずつ、ほか `take`・`member?` など）。
ほとんどが終わらない呼び出しで、5 秒ずつだと最悪 6 時間かかるので、やり直さなかった。README に件数を書いた。

規則を足した順と、そう決めた理由:

- **`internal-helper`（`__` で始まる名前）を先頭近くに置いた。** 差の 22%（15,178 呼び出し）が
  `__split`・`__product_next`・`__struct_init_fwd` などの helper で、どれも Ruby で書いたメソッドが自分で作った
  引数で呼ぶもの。呼ぶ側の公開メソッドは別に洗っているので、ここに `"".__split(0)` の文言の差を数えても
  直す線の判断には効かない。後ろに置くと argc や文言の規則に混ざって数を膨らませるので、crash・timeout の
  次に置いた（helper の panic があれば crash に入る）。
- **`kw-dropped` は「キーワード無しの同じ呼び出し」と比べて決める。** `auto:` の大きな組の一つが
  `(0).to_s(k: 1)` で rc2 が `"0"`、SabiRuby が "Hash cannot be converted to Integer"。rc2 がキーワードの Hash を
  捨てているのか確かめるには、同じ受け手・同じ引数でキーワードの無い呼び出しの答えと比べればよい。
  表にはその呼び出しが必ずある（キーワードは最小の個数の行に付けるので、同じ個数の行が全部ある）。
  `compare.py` に `R_nokw`/`S_nokw` を渡し、「rc2 の答えがキーワード無しと同じで、SabiRuby の答えは違う」を
  規則にした。26 メソッド・706 呼び出し。`[1].first(k: 1)` は rc2 が 1、SabiRuby と CRuby は TypeError。
  README の Known deviations は `push` の理由に「mruby は他ではキーワードの Hash を位置引数として渡す」と
  書いているが、この 26 メソッドでは rc2 は捨てている（気づいた点）。
- **`argc-narrow` を割った。** 一番大きい規則（14,661）の例 `("abc").chomp(nil, nil)` を 1 行で両方に打つと、
  rc2 も ArgumentError で同じだった。表の呼び方は `r.__send__(m, *a)`（`runner.rb`）で、splat で渡している。
  `q_send.rb` で `chomp(nil, nil)`・`chomp(*a)`・`__send__(:chomp, nil, nil)`・`__send__(:chomp, *a)` を比べると、
  rc2 は splat のときだけ TypeError（nil cannot be converted to String）、SabiRuby はどれも ArgumentError。
  rc2 は `chomp`・`chomp!`・`to_i`・`alias_method` を MRB_ARGS_ANY（4096、`tools/rc2-aspec/rc2-aspec.tsv`）と
  宣言して `mrb_get_args` で数えるので、splat で来ると数える前に最初の引数を変換している、と読める
  （`1.+(*[1, 2])` は splat でも ArgumentError なので、splat 全部ではない）。この 4 つを `argc-splat`（12,042）に
  分け、見立ては C（rc2 の中で呼び方によって例外が変わる）。残りの `argc-narrow`（2,619）は `Array#sample`
  （rc2 は opt 2）、`Class#initialize`（opt 1）、`Data#initialize` で、literal の呼び出しでも違う（`q_argc.rb`）。
  X1 の数を読むときの注意: 表の呼び出しは全部 splat なので、rc2 で宣言が ANY のメソッドの個数の誤りは
  この形でしか見ていない。
- **`method-missing-name` を `not-a-symbol` の前に移した。** `not-a-symbol` に `method_missing(0)`（rc2 TypeError、
  SabiRuby NoMethodError '?'、例外のクラスの差）と `local_variable_get(nil)`（"nil" と "NilClass"、文言の差）が
  混ざっていたので、前者を `method-missing-name` に寄せて A、後者を B にした。
- **`bytesplice` を 1 つにまとめた。** `bytesplice-arity`（"arumgnts"）のほか、`conv-int-msg`・`conv-order` にも
  `bytesplice` の行が 3,000 ほど入っていた。rc2 は 2 引数を (range, str) と読み、境界より先に変換し、個数の誤りは
  値を見た後に言う。原因は 1 つ（引数の読み方）なので名前で取った。panic の 51 は `crash` に残した。
- **`join-empty` の規則を直した。** 前の規則は `"(, "` で始まる形しか取らず、`step(true, )` を落としていた。
  空の項を取り除いた形（`drop_empty`）どうしが等しいことを規則にした。`""` を残して `[]` だけ落とす形
  （`each(1, , )` と `each(1, )`）も同じ原因として入る。
- **2 回目の規則**（自動の組の 2 呼び出し以上を大きい順に）: `bigint-to-float`、`math-nan-domain`、
  `visibility-args`、`int-div-nonfinite`、`regexp-match-nil`、`merge-partial`、`fill-empty-range`、`set-reinit`、
  `set-uninit`、`proc-init-copy`、`rational-minus`、`lenient-arg`、`struct-const-name`、`class-new-super`、
  `time-year`（前の `time-year0` を年 0 以外にも広げた。最初の版は `or` と `and` の優先順位の誤りで Time の
  行を全部取っていたので括弧を足した）、文言の差の受け皿 `conv-msg-other` と `msg-other`。

1 行の再現はスクラッチパッドの `q.rb`（66 行、rc2・SabiRuby・CRuby 3.2 で実行）、`q_send.rb`・`q_argc.rb`
（splat）、`q_str.rb`（String#+）、`g6.rb`（凍結したクラスへの `A::Y =`）で確かめた。出力の要点は README の
表に書いた。

**どこで切ったか。** 2 回の後、`auto:` は 31 組・124 呼び出し（差の 0.18%）、いちばん大きい組が 22。
依頼の目安「残りの合計が全体の差の数 % 以下」を十分下回るので、ここで止めて「未分類」として件数だけ載せた。

**見立ての表。** 原因ごとの見立て・直す大きさ・本の記述は `causes.py` の `VERDICTS` に 1 行ずつ置き、
`compare.py` が `x1-causes.tsv` の列に書く（README の要約の数はこの表から数えた）。本に関わるかは
`book_mruby3/contents/*.re` と `data/code` をメソッド名・文言で grep して、当たった行を読んで決めた。

## X2 の原因ごとのまとめ

`x2-programs.tsv` と `x2-asserts.tsv` を読み、違いを 1 つずつ X1 の原因に寄せるか、新しい原因にした
（`x2-causes.tsv`、手で書いた表）。本の `data/code` と kit の samples は同じファイルが 19 本あり、数は本の側で数えた。

X1 に寄せたもの: `corelib_error_messages.rb`（`conv-float-msg`）、`corelib_kernel.rb` と `gc_generational.rb` の

## 気づいた点

（README の「原因」の表と同じものは書かない。表に載らなかったことだけ。）

- **`sabiruby` コマンドは出力を終わるまで出さない**（CLI、`cli/src/main.rs:295`）。途中で panic すると、それまでに
  `puts` したものも消える（`"abc".bytesplice(0, 0)` の前の行が 1 行も出ない）。rc2 の `mruby` は書いた分が残る。
  デバッグで困る種類の差。属する先: CLI。
- **`sabiruby compile` は標準入力を読まない**（`-` を "Cannot open program file" にする）。mrbc は読む。小さい。
- **本の `exp_AREF_redefine.rb` は `$stdout.write` を使う**。SabiRuby には `$stdout` が無い（mruby-io を持たない）
  ので NoMethodError で止まる。本の側の書き方か、SabiRuby の側の欠けか。属する先: 本／SabiRuby の gem の範囲。
- **rc2 の `String#bytesplice` の文言に綴りの誤り**: "wrong number of arumgnts"（rc2 の mruby-string-ext）。
  本家への報告の候補。
- **README の Known deviations の `push` の理由が、この洗い出しの結果と合わない**（`README.md` の
  "`Array#push` with keyword arguments"）。「mruby otherwise hands the keyword Hash of a C function that takes no
  keywords on as a positional argument」とあるが、`[1].first(k: 1)`・`0.to_s(k: 1)`・`a.[]=(0, 0, k: 1)` など
  26 メソッドで rc2 は Hash を捨てている（原因 `kw-dropped`）。決定そのものではなく、理由の書き方の問題。
  属する先: VM の docs／著者の判断（`kw-dropped` は「要判断」にした）。
- **custom テストの 2 本が README の Known deviations に無い**: `tests/custom/eval_class_eval_scope.rb`
  （master 300cc9532 の直し）と `eval_outer_scope.rb`。方針（`design/compatibility.md`）は 3 か所に書くことを求める。
  属する先: VM の docs。
