## W1. ネイティブに引数の宣言を持たせる

### rc2 の作り（確かめたところ）

- `define_method_id`（`src/class.c:1105`）は `m.flags |= aspec`。ROM の表は `MRB_MT_ENTRY(fn, sym, flags)`
  （`include/mruby/class.h:133`）で、flags の下 24 ビットが `MRB_MT_ASPEC`。
- 検査は `check_argument_count`（`src/vm.c:1580`）。`min = REQ + POST`、`max = REST ? 無限 : min + OPT`。
  キーワードを取らないメソッドでは、空でないキーワードの Hash を 1 つに数える。呼ぶ所は OP_SEND の関数の枝
  （`:3728`、`MRB_METHOD_FUNC_P` なら必ず）、`mrb_f_send`（`:1759`）、`exec_irep`（`:1610`）。RProc の cfunc は
  OP_SEND では `MRB_PROC_NOARG` だけを見る（`:3721`）。**`mrb_funcall` 系（C からの呼び出し）は検査しない**
  （`:1535` 付近、`MRB_METHOD_CFUNC(m)(mrb, self)` を直接呼ぶ）。この最後の点が下の「funcall」の判断に効く。
- `Method#arity` は mruby-method が関数の項目から RProc を作り（`method.c:381`）、`mrb_proc_set_cfunc_aspec`
  で 13 ビットに圧縮して持たせ、`mrb_proc_arity`（`src/proc.c:423`）が広げて読む。圧縮では req・opt が 7、
  post・key が 3 を超えると切り詰めて rest を立てる。aspec が 0 なら `MRB_PROC_NOARG`（arity 0）、圧縮した
  ビットが全部 0（`MRB_ARGS_NOBLOCK` だけ）なら -1。

### 宣言の書き方

`src/object.rs` に `pub struct Aspec(u32)` を置いた。中身は rc2 の `mrb_aspec` と同じビットの並びで、
作り方も C のマクロと同じ名前にした: `Aspec::req(1) | Aspec::opt(1)` が `MRB_ARGS_REQ(1)|MRB_ARGS_OPT(1)`、
`Aspec::none()`、`Aspec::any()`（= `rest()`）、`post(n)`、`key(n, kdict)`、`block()`、`noblock()`。
`bounds()` が `check_argument_count` の min と max、`arity()` が圧縮してから `mrb_proc_arity` の式で読んだ値を返す。
ビットを rc2 と同じにしたのは、圧縮の切り詰め（`req1|opt31` のような rc2 の宣言が実際にある）まで同じ答えを
出すためである。

宣言はメソッドと一緒に持つ: `Method::Native(NativeFn, Aspec)`、`MethodRef::Native(NativeFn, Aspec)`。
`Method` は 16 バイトのまま（関数のポインタ 8 と、判別子と u32 が残りの 8 に入る）。クロージャは
`ClosureBody { f, aspec }`（`arity: i64` を置き換えた）。

定義の口は `mrb_define_method` に寄せて名前に `_args` を付けたものを足した:
`define_method_args(class, name, aspec, f)`、`define_methods_args(class, &[(name, aspec, f)])`、
`define_private_method_args`、`define_private_methods_args`、`define_module_function_args`、
`define_closure_args`。宣言の位置は C と違って名前のすぐ後（関数の前）にした。表の行はクロージャが
長く、末尾に置くと名前と宣言が 200 字離れて読み比べられないからである。今までの `define_method` などは
署名を変えず `Aspec::any()`（検査なし、arity -1）を渡すだけにした。rc2 で宣言の無い cfunc の RProc
（arity -1、検査なし）と `MRB_ARGS_ANY` は、検査も arity も同じ答えになるので、「宣言なし」に別の印は
要らなかった。`define_fn` は Rust の署名の数を `Aspec::req(n)` にした（`call_ruby` の中の `check_argc` は
残したが、VM が先に同じ文言で止める）。

### 検査の場所

`Vm::check_aspec(aspec, args)`（`src/vm.rs`、`#[inline(always)]`）。`bounds()` はシフトと足し算だけで、
外れたときだけ `#[cold] #[inline(never)] aspec_argnum_error` に行き、そこで文言を作る（キーワードを取ると
宣言したメソッドなら、`pending_kw` と同じ最後の Hash を数から引いて数え直す）。命令ループの腕に入ったのは
比較 2 つと分岐だけである。

入れた所: OP_SEND のネイティブとクロージャの腕（`op_send_vis`、引数を並べた直後、`call_native_direct` の前）、
`Vm::funcall` のネイティブとクロージャの腕、`send_in_frame`（`send` の転送）、`Method#call` の
`call_native`／`call_closure`（`ext_method.rs`）。OP_SEND で外れたときは `native_raised` を呼んでから返す。
最初これを忘れて `custom/native_backtrace` の `"abc".center` が落ちた: rc2 は C の関数を呼ぶ前に
`cipush` しているので backtrace に `in center` が入る。`native_raised` を呼ぶと SabiRuby も入る。

**funcall も検査する（rc2 と違う所）。** rc2 の `mrb_funcall` は宣言を見ないが、そこから呼ばれた C の関数は
`mrb_get_args` で自分で数える。SabiRuby で本体の `argc!` を外すと、funcall で数の違う呼び出しが来たときに
`a[0]` が範囲外で panic する。そこで funcall でも検査することにした。答えが変わるのは「本体が数を数える前に
別の誤りを出す」場合だけで、見つかったのは 1 つ: `"a".freeze.slice!`（引数なし）。rc2 の regexp の
`slice!`（`MRB_ARGS_ANY`）は正規表現でない引数を `mrb_funcall_argv(__slice_bang)` に渡し、core の
`mrb_str_slice_bang` が数より先に凍結を見るので FrozenError、SabiRuby は ArgumentError になった。
`ext_regexp.rs` の `str_slice_bang` の転送の前に `check_frozen` を置いて合わせた。

### 宣言の値: rc2 の VM から集める

計画は「rc2 の `MRB_MT_ENTRY` と `mrb_define_*method` の呼び出しを読む」だったが、ソースを読むと
クラスを表す C の変数（`s`、`krn`、`mrb->string_class`、`mrb_singleton_class_ptr(...)`）を Ruby の名前に
直す所が手作業になる。代わりに rc2 の VM 自身に聞いた: `tools/rc2_aspec.sh` はイメージの中のソースを
使い捨てのコンテナに写し、既定の gembox に小さな gem（`tools/rc2-aspec/gem/src/aspec_dump.c`、
`Kernel#__aspec(mod, name)`）を足して建て、`tools/rc2-aspec/dump.rb` が全部のメソッドについて
`mrb_method_search_vm` で項目を引き、`MRB_METHOD_FUNC_P` なら `MRB_MT_ASPEC(m.flags)`、cfunc の RProc なら
`mrb_proc_decompress_caspec` を書き出す。読み出しは VM が検査に使うマクロそのままなので、表の値は
「ソースの読み方」ではなく rc2 が実際に検査する値である。建てたものは同じ gembox なので、メソッドの一覧は
イメージの `mruby` と 1545 行が 1 行も違わないことを確かめた（`diff` が空）。main の特異メソッド
（`to_s`、`inspect`、`public` など 7 つ）は `ObjectSpace` に出ないので別に書き出した。結果は
`tools/rc2-aspec/rc2-aspec.tsv`（1552 行: func 1089、cproc 23、ruby 440）。Ruby のメソッドは `OP_ENTER` の
被演算子（同じビットの並び）も書いた。

### SabiRuby の定義と突き合わせる

ネイティブの定義は 948 か所（表の行と単独の呼び出し）あり、どのクラスに入るかはソースからは決まらない
（`define_methods(sc, fns)` を 2 つのクラスに使う、`c.kernel` と `k` など）。そこで 3 段で機械的にやった
（道具はスクラッチパッドの `l10/rewrite.py`・`assign.py`・`finalize.py`）:

1. 全部の定義を `_args` の形にして、宣言の所に番号つきの仮の値 `Aspec::__site(N)`（上のビットに印）を
   入れる。`def_method_raw` が印を見て `(N, クラス, 名前)` を記録し、仮の値は検査を素通りにする。一時の
   テストで初期化した VM の記録を書き出した。948 のうち 940 か所が初期化で通る（通らない 8 か所は下）。
2. 各か所の (クラス, 名前) を rc2 の表で引く。持ち主が同じなら rc2 の値（859 か所）。持ち主が違う
   （SabiRuby の `Numeric#<` に対し rc2 は `Integer#<` と `Float#<`、SabiRuby の `Object#to_s` に対し rc2 は
   `Kernel#to_s`）ものは、両方で「各クラスがその名前で行き着く持ち主」を書き出し（dump.rb の `@` の行）、
   SabiRuby のそのメソッドに行き着くクラスたちが rc2 で何を呼ぶかを集めた。答えが全部同じ見え方（範囲と
   文言の形）なら使う。rc2 が Ruby のメソッド（`Comparable#<` の `def <(other)`）でも必須の数だけなら文言は
   同じなので同じ扱いにした。最初は「祖先か子孫に同じ名前があるか」で探したが、`Object#to_s` が全部の
   クラスの `to_s` と当たって「食い違い」になったので、この「行き着く先」の方法に替えた。
   rc2 にネイティブが無いもの（Task、CMath、require、sleep、`__ary_cmp` など、rc2 では Ruby の `Kernel#p`
   など）は、本体の先頭の `argc!` と同じ意味の宣言（50 か所）、`argc!` が無ければ `Aspec::any()`（31 か所）。
   食い違い（同じか所に 2 つの値）は 0 だった。
3. 仮の値を宣言で置き換え、本体の先頭の `argc!` が宣言と同じ範囲なら消す。名前の付いた関数が本体のものは、
   それを使う全部のか所が同じ宣言のときだけ消した（同じ名前の関数が 2 つのファイルにある 9 つは手で見た）。
   消して使われなくなった引数（`a` 54、`vm` 12）と `use crate::argc` 21 は、コンパイラの警告の位置
   （`--message-format=json` の span）を読んで機械的に `_a` にし、行を消した。

初期化で通らない 8 か所は rc2 のソースの行を見て書いた: Struct が作るクラスの `new`・`[]`（ANY）・`members`・
`keyword_init?`（NONE、`struct.c:250-253`）、Data が作るクラスの `new`（ANY）・`members`（NONE、
`data.c:291-292`）、regexp の無いビルドの `sub`・`gsub`（rc2 に対応が無く、本体に `argc!` が無いので any）。
単独で直したもの: `sprintf`／`format` のループ（`sprintf.c:1225`、ANY）。Struct と Data の読み書きの
メソッドは rc2 で宣言の無い cfunc の RProc（`make_struct_define_accessors`）なので宣言しない。ただし Data の
読み手の最初の 4 つは rc2 が `MRB_ARGS_NONE` の関数で定義する（`DATA_DIRECT_REF_MAX`、`data.c:152`）ので、
その数を `ext_struct.rs` に出どころつきの const で置いた（変えると rc2 と答えが変わる不変量）。

### 別名で取っておかれる core のメソッド

arity を比べた後に 4 つ（`String#__index`・`__byteindex`・`__byterindex`・`__slice_bang`）が残った。
mruby-regexp は core の `index` などを `__index` の名前で取っておいてから自分の `index`（ANY）を被せる。
突き合わせの run では `String#index` の名前が regexp の版に上書きされた後なので、core のか所にも regexp の
ANY が付いていた。core の `index`・`byteindex`・`byterindex`・`slice!` には rc2 の `__` の名前の値
（REQ(1)|OPT(1)）を、`split` には `__split` の値（ANY、本体の `argc!(0, 2)` を戻した）を付け、
理由をコメントにした。regexp の無いビルドでは core の版がそのまま `String#index` なので、これで rc2 の
regexp 無しと同じになる。

## W3. `define_method` の block を strict に

rc2 の `define_method_m`（`src/class.c:4163`）は `mrb_proc_copy` で block を写し、写しに `MRB_PROC_STRICT` を
立ててメソッドにする（元の block は proc のまま）。SabiRuby は block の Proc そのものを `Method::Ruby` に
入れ、環境の無い Proc ならその `target_class` を書き換えていた。`object.rs` に `method_proc`（ProcData を
写して `strict = true`、環境が無ければ写しの `target_class` を定義先に）を置き、`define_method` と
`define_singleton_method` の両方から使う。`C.new.g(1, 2, 3)` が "given 3, expected 1"、`g()` も誤り、
`arity` -2、`define_method(:k, &pr)` の後も `pr.lambda?` は false で `pr.call(1)` は `[1, nil]`、
`return` はメソッドから返る — どれも rc2 と同じ（`tests/custom/rc2_leftovers10.rb` の W3 の節）。

## W4. 特異クラスで undef された `new` の文言

rc2 は `mrb_undef_class_method` で特異クラスに undef の項目を置く。呼ぶと `method_missing` の
"undefined method '%n' for %T"（`src/class.c:4542`）で、`%T` は受け手のクラスなので `Integer.new` は
"for Class"。SabiRuby は Rational・Complex・Method・UnboundMethod・MatchData・Data では既に同じことをしていたが、
Integer・Float・Symbol・NilClass・TrueClass・FalseClass は `Class#new` の割り当て（`InstanceKind::NoAlloc`）が
"for Integer" と答え、Binding は `allocate` まで "new" と言っていた。`builtins/mod.rs` の
`undef_class_methods` で rc2 の呼び出しの一覧（`numeric.c:2585,2597`、`symbol.c:1372`、`object.c:382-392`、
`binding.c:505-506`）の分を特異クラスで undef する。`respond_to?(:new)` も false、`singleton_methods` に
`:new` が出るのも rc2 と同じになった。

ネイティブの腕が太ったこと（`pending_kw` を戻して `native_raised` を呼ぶ誤りの枝）か、`MethodRef::Native` が
2 つの値を持つようになったことによる、Ruby の呼び出しの腕のコード配置かレジスタの割り当ての変化だと
見ている（確かめていない）。案: 誤りの枝を `#[cold]` の関数 1 つにまとめて腕を細くする、宣言を
`MethodRef` ではなく関数の側（表）に置いて `MethodRef` を元の大きさに戻す。どちらにするかは著者の判断。

### 追記（2026-10-18）: 誤りの枝を 1 つの cold 関数に

## 残ったこと

- **呼び出しの道の速さ**（上の「数値」）: `call_kwargs` が A/A の幅を超えて 1〜4% 遅かったので一度止めた。
  誤りの枝を cold 関数に出して幅の中に戻した（追記）。

- funcall からの呼び出しでも宣言を検査する（rc2 はしない）。違いが出るのは本体が数より先に別の誤りを出す
  場合で、見つけた `slice!` は合わせた。ほかに同じ形があるかは全部は探していない。
- `argc!` の残り 33（上）。宣言と意味が違うものは rc2 の `mrb_get_args` の写しとして残した。

## 気づいた点

- **`[1].push(k: 1)`**（VM、base から）: rc2 は `[1]`、SabiRuby は `[1, {k: 1}]`。キーワードだけを
  `MRB_ARGS_ANY` の関数に渡したとき rc2 は Hash を捨てる（`mrb_get_args("*")` がキーワードを位置引数に
  入れない）。今回の変更の前から同じで、`tests/custom/rc2_leftovers10.rb` から外した。backlog に入れる話。
- **rc2 の `define_singleton_method(:x, a_proc)` は ArgumentError**（rc2 の性質）: `Kernel#define_singleton_method`
  の宣言が `REQ(1)|BLOCK` なので 2 つ目の引数は検査で止まる（本体の `mrb_get_args("n|o&")` は受けるのに）。
  SabiRuby も今はそうなる。本家の中で食い違う形だが、方針の「明らかな不具合」かは判断していない。
- **`Kernel#__id__` と `BasicObject#!=`**（持ち主の違い）: rc2 は `BasicObject#__id__`、`!=` は Ruby。
  答えは同じ。
- **本の素材**: rc2 の宣言は `mrb_funcall` では検査されない。C の関数は VM の検査と `mrb_get_args` の 2 段で
  数を見ていて、`slice!` のように C から C へ渡すと 2 段目だけになり、誤りの順序が変わる。
- **本の素材**: 宣言の値を集めるとき、ソースを読むより VM に聞く方が早く正確だった（クラスを表す C の変数を
  名前に直す所が要らない）。gem 1 つ（50 行）を足して建てるだけで、建て直しは 1 分。
