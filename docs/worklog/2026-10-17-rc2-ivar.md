## Q1. `obj_iv_p` の外の値

### rc2 を読む

`/home/kishima/book/ref/mruby`（作業ツリーは rc2 の `c17ffcc24`）の `src/variable.c`。

- `obj_iv_p`（`:546`）は `mrb_unboxed_type` が OBJECT・CLASS・MODULE・SCLASS・HASH・CDATA・
  EXCEPTION のときだけ真。
- `mrb_iv_get`（`:611`）: 偽なら nil。`mrb_iv_set`（`:733`）: 偽なら ArgumentError "cannot set
  instance variable"。真なら `mrb_obj_iv_set`（`:683`）で、そこで初めて `mrb_check_frozen`。
  つまり **型の検査が凍結の検査より先**で、凍結した String も Integer も FrozenError でなく
  ArgumentError になる。
- `mrb_iv_defined`（`:783`）: 偽なら FALSE。`mrb_iv_foreach`（`:707`）、
  `mrb_obj_instance_variables`（`:984`）: 偽なら何もしない（`[]`）。
- `mrb_iv_remove`（`:919`）: 偽なら undef。真なら `mrb_check_frozen` してから探す。
  `remove_instance_variable`（`src/kernel.c:594`）は undef を NameError "instance variable @x not
  defined" にするので、凍結した Array では NameError、凍結した Object では（変数が無くても）
  FrozenError。
- `OP_GETIV`／`OP_SETIV`（`src/vm.c:3269`、`:3293`）: 速い道は `MRB_TT_OBJECT` で shape の
  ある既存の枠だけ。それ以外は `mrb_iv_get`／`mrb_iv_set` に落ちる。
- `instance_variable_get/set/defined?`（`mrbgems/mruby-metaprog/src/metaprog.c`）: 名前の検査
  （`mrb_iv_name_sym_check`）の後に上の関数。名前が悪ければ型より先に NameError。
- `attr_reader`／`attr_writer` も `mrb_iv_get`／`mrb_iv_set` を通る（下の確かめで、
  Array のサブクラスへの `w = 3` が ArgumentError、凍結した Object への `x = 1` が FrozenError）。
- `init_copy`（`src/class.c:4349`）: `mrb_iv_copy` は OBJECT・SCLASS・HASH・CDATA・EXCEPTION
  （と CLASS・MODULE）だけ。他の型はそもそも iv を持たないので、コピーするものが無い。

型が何になるかは `MRB_SET_INSTANCE_TT` で見た: Range は `MRB_TT_RANGE`（`src/range.c:596`）、
Set は `MRB_TT_SET`（`mruby-set/src/set.c:1536`）、Random は `MRB_TT_ISTRUCT`
（`mruby-random/src/random.c:624`）、Rational・Complex はそれぞれの型、Time は `MRB_TT_CDATA`、
Task と `Task::Queue` は `MRB_TT_DATA`（= CDATA、`include/mruby/value.h:231`）、Binding と
Method は `MRB_TT_OBJECT`。Struct と Data は `MRB_TT_STRUCT`。

### rc2 の型の表

スクラッチ `iv/types.rb` を rc2 と SabiRuby（前）で回した。各行は `instance_variable_set`、
`instance_variable_get`、`instance_variable_defined?`、`instance_variables`、
`remove_instance_variable` の答え。

| 値 | rc2 の型 | rc2 | SabiRuby（前） | SabiRuby の kind |
|---|---|---|---|---|
| Object、Class、Module、特異クラス | OBJECT/CLASS/MODULE/SCLASS | 持てる | 持てる | Object、Class |
| Hash、そのサブクラス | HASH | 持てる | 持てる | Hash |
| Exception（サブクラス） | EXCEPTION | 持てる | 持てる | Exception |
| Time | CDATA | 持てる | 持てる | Object |
| Method、UnboundMethod、Binding、Enumerator | OBJECT | 持てる | 持てる | Object |
| Regexp、MatchData | CDATA | 持てる | 持てる（順は下の気づいた点） | Regexp、MatchData |
| String、そのサブクラス | STRING | ArgumentError／nil／false／[]／NameError | 持てる | String |
| Array、そのサブクラス | ARRAY | 同上 | 持てる | Array |
| Range | RANGE | 同上 | 持てる | Range（`allocate` 直後は Object） |
| Proc、lambda | PROC | 同上 | 持てる | Proc |
| 大きな Integer | BIGINT | 同上 | 持てる | BigInt |
| Integer、Float、Symbol、true、false、nil | 即値 | 同上 | FrozenError "can't modify frozen Integer" | 即値 |
| Struct | STRUCT | 同上 | 持てる | Array |
| Data | STRUCT | 同上 | FrozenError（凍結しているので） | Array |
| Fiber | FIBER | 同上 | 持てる | Fiber |
| Rational、Complex | RATIONAL/COMPLEX | 同上 | FrozenError | Object（隠れた iv `__num` など） |
| Random、そのサブクラス | ISTRUCT | 同上 | 持てる | Object（隠れた iv `__state`、`__seed`） |
| Set、そのサブクラス | SET | 同上 | 持てる | Hash |

ホストの値（`Vm::data_new`、`ObjKind::Data`）と Task は rc2 の CDATA に当たるので持てる側。
rc2 の既定のビルドには mruby-task が入っていない（`Task` が未定義）ので、Task は
`MRB_SET_INSTANCE_TT(task_class, MRB_TT_DATA)`（`mruby-task/src/task.c:1896`）を読んで決めた。

### SabiRuby の形と、写し方

SabiRuby の `ObjKind` は rc2 の型と 1 対 1 ではない。表の右の列のとおり、Set は Hash の形、
Random・Rational・Complex は隠れた iv を持つ普通の Object、Struct と Data は Array の形を借りて
いる。kind だけで `obj_iv_p` を写すと、Set（Hash の形）、Random・Rational・Complex（Object の
形）、`Range.allocate` 直後の Range（Object の形）を取りこぼす。

考えた案:

1. kind で決め、Object と Hash の形のときだけクラスの鎖をたどって Set・Random などの子孫かを
   見る。`@x = v` のたびに（普通のオブジェクトでも）鎖をたどることになり、SETIV の速い道に
   ループが入る。捨てた。
2. オブジェクトに印を 1 つ持たせる。`HeapObject` は `class: ObjId`（4 バイト）の後に `frozen`
   と `binary` の 2 つの bool があり、もう 1 つ bool を足しても詰め物の中に収まる見込み。
   印を立てるのは割り当てのときだけで、SETIV／GETIV は既に手元にある `HeapObject` の kind と
   bool を見るだけで済む。これを採った。

変えたところ:

- `HeapObject::no_ivars`（`src/object.rs:485`）と `HeapObject::iv_p`（`:497`）。`iv_p` は
  kind が Object・Class・Hash・Exception・Data・Task・Regexp・MatchData で、かつ `no_ivars` で
  ないとき真。kind が後で変わる（Range の `initialize` が Object を Range にする）ことがあるので、
  kind の判定は印に焼き込まず毎回見る。
- `InstanceKind` に `Set`（Hash の形、印つき）と `Istruct`（Object の形、印つき）を足した
  （`src/object.rs:120` 付近）。`Vm::instance_alloc`（`src/builtins/mod.rs:199`、`:212`）は
  `Range`・`Set`・`Istruct` のとき印を立てる。Set のクラスは `InstanceKind::Set`
  （`ext_set.rs`）、Random のクラスは `InstanceKind::Istruct`（`ext_random.rs`）にしたので、
  サブクラスも祖先の `instance_kind` をたどって印がつく。
- Rust の中で直接割り当てるもの: Rational（`ext_rational.rs:66`）、Complex
  （`ext_complex.rs:56`）、既定の乱数生成器（`ext_random.rs:351`）。
- `Object#dup`（`src/builtins/object.rs:556`）は印を写す（`clone` は `dup` を通る）。隠れた iv
  （Random の状態など）はこれまでどおり写す。`init_copy` が iv を写さない型でも、こちらでは
  それが内部状態なので写さないと `Random#dup` が壊れる。スクリプトが iv を置けないので、写して
  見えるものは増えない。
- `Vm::iv_get`／`iv_set`／`iv_defined`／`iv_remove`／`iv_names`（`src/vm.rs:1144`〜`:1192`）:
  `mrb_iv_get`／`mrb_iv_set`／`mrb_iv_defined`／`mrb_iv_remove`／`mrb_obj_instance_variables`。
  `iv_set` は `iv_p` → 凍結の順。ArgumentError の組み立ては `#[cold] #[inline(never)]` の
  `iv_set_refused`（`:1167`）に出した。
- 通り道をそれに替えた: `Op::Getiv`（`:4461`）、`Op::Setiv`（`:4466`、速い道は
  `iv_p() && !frozen` のときの `Heap::ivar_set` だけで、それ以外の腕は `self.iv_set(...)?` 1 行。
  命令ループの腕に文言の組み立てを入れない、という L1・M2 の教訓どおり）、`attr_reader`／
  `attr_writer` の 2 か所ずつ（`:2450`、`:5520`）、`Kernel` の `instance_variable_get/set/
  defined?`・`instance_variables`・`remove_instance_variable`（`object.rs` の素のものと
  `ext_metaprog.rs` のもの）、`defined?(@x)` が呼ぶ `__defined_ivar?`（`kernel.rs`）。
- `Object#inspect`（`obj_inspect`）は `iv_p` の物だけ iv を並べる。前は Random の
  `p Random.new(1)` が `#<Random:0x… __state=…, __seed=1>` と内部を見せていた（rc2 は
  `#<Random:0x…>`）。これも直った。
- ついでに直ったもの: `attr_writer` が凍結を見ていなかった（`A.new.freeze.x = 1` が通って
  いた。rc2 は FrozenError）。`mrb_iv_set` を通すと凍結の検査が入る。SETIV の即値の TypeError
  "can't set instance variable on an immediate" と `object.rs` の "can't set instance variable"
  も ArgumentError になった。

内部の `Heap::ivar_get`／`ivar_set` はそのまま（隠れた iv を書く VM 自身の道）。

### ホストの API

`Vm::ivar_get`／`Vm::ivar_set`（`ObjId` を取る）は変えなかった。rc2 の C API で
`struct RObject *` を取る `mrb_obj_iv_set_force` に当たり、型も凍結も見ない。`VmResult` を
返すように変えると API が壊れ、ホストが自分の値に書く用途（rubevy の task の
`@rubevy_entity` など）には検査が要らない。rustdoc に「Ruby から見えるのは iv を持てる値の
ときだけ」と書き足した。

## Q2. `Integer(2**70)`

rc2 の `mrb_f_integer`（`mruby-kernel-ext/src/kernel.c:159`）: nil、Float
（`mrb_float_to_integer`）、Integer、String の腕の後、基数があれば `mrb_obj_as_string` して文字列
として読み、無ければ `mrb_ensure_integer_type`（`src/object.c:631`）。そこは大きな Integer を
そのまま、Rational は `mrb_rational_to_i`、Complex は `mrb_complex_to_i`（どちらも C の関数で、
メソッドは呼ばない）、残りは TypeError "%Y cannot be converted to Integer"。`mrb_f_float`
（`:213`）は String でなければ `mrb_ensure_float_type`（`src/object.c:715`、BIGINT・RATIONAL・
COMPLEX も変換）。

SabiRuby の `kernel_integer`（`src/builtins/ext_kernel.rs:267`）は大きな Integer を最後の腕に
落とし（"can't convert Integer into Integer"）、Float は `libm::trunc(f) as i64` で飽和させ
（`Integer(1e30)` が 9223372036854775807）、NaN は FloatDomainError（rc2 は RangeError "float
NaN out of range"。`Float#to_i` は rc2 でも FloatDomainError なので、`Integer()` の方だけ違う）。
`kernel_float` は大きな Integer・Rational・Complex を TypeError にしていた。文言も CRuby 風
（"can't convert X into Integer"）だった。

変えたところ:

- `numeric::float_to_integer`（`src/builtins/numeric.rs:475`）: `mrb_float_to_integer`。NaN と
  無限は既存の `float_out_of_range`、範囲の外は既存の `float_to_int` で大きな Integer。
- `ensure_integer_type`（`ext_kernel.rs:305`）: 大きな Integer はそのまま、Rational は
  `ext_rational::to_i`（`Rational#to_i` の中身を関数に出した）、Complex は
  `ext_complex::complex_to_i`（`pub(crate)` にした）、残りは "%Y cannot be converted to
  Integer"。
- `kernel_float`（`:314`）: nil の文言、Complex は `ext_complex::to_f64`、他は既存の
  `numeric::num_f64`（Integer・Float・Rational・大きな Integer）、残りは "%Y cannot be converted
  to Float"。
- 途中で 1 つ: `Integer(2+1i)` の RangeError が rc2 は "can't convert 2+1i into Integer"、
  SabiRuby は "(2+1i)"。`mrb_complex_to_i` の `%v` は `to_s` で、SabiRuby の `to_real`
  （`ext_complex.rs`）は `inspect` を使っていた。`Complex#to_i`／`to_f` そのものの文言の差で、
  `Integer()` がそこを通るようになって見えた。`as_string`（`to_s`）に替えた。

`tests/custom/kernel_integer_wide.rb`: 大きな Integer（正負、基数つき）、大きな Float、NaN、
無限、Rational（大きな分子も）、Complex（虚部 0、虚部あり、Float・Rational・大きな Integer の
実部）、Object・Symbol・Array・true、`Float()` の同じ並び、`Rational()`／`Complex()` に大きな
Integer（これは前から合っていた）。`.expected` は rc2 の出力、SabiRuby（後）は一致。

## 気づいた点

- **VM / rc2 との差（記録だけ）**: Regexp の `instance_variables` の順。rc2 は
  `[:@flags, :@source, …]`、SabiRuby は `[:@source, :@flags, …]`（`ext_regexp.rs` が `@source`
  を先に書く）。スクラッチ `iv/types.rb` の Regexp の行。直していない。
- **VM / rc2 との差（記録だけ）**: `remove_instance_variable` が名前を検査しない
  （`src/builtins/object.rs` の素の `remove_instance_variable` は `sym_arg` だけ。rc2 は
  `mrb_iv_name_sym_check`）。`"s".remove_instance_variable(:x)` と
  `Object.new.remove_instance_variable(:x)` は rc2 で NameError "'x' is not allowed as an
  instance variable name"、SabiRuby は NameError "instance variable x not defined"（スクラッチ
  `iv/rm.rb` で確かめた）。
- **VM / rc2 との差（記録だけ）**: 多重代入の `to_ary`。`class MyAry; def to_ary; [1, 2, 3];
  end; end; a, b, c = MyAry.new` が rc2 は `[MyAry, nil, nil]`、SabiRuby は b と c にも
  オブジェクトが入る。playground の `overview_diff.rb` を両方で回して見つけた。base（`9a32679`）
  でも同じなので今回の変更とは関係ない。本の overview.re「暗黙の型変換をしない」に関わる。
- **VM（内部）**: `Kernel#instance_variable_names`（`kernel.rs:32`、rc2 には無いメソッド）は
  `iv_p` を見ず、隠れた iv（`__num` など）も返す。今回の範囲の外なので触っていない。
- **ホストの API**: `Vm::ivar_set` は持てない値にも書け、Ruby からはそれが見えない。rustdoc に
  書いたが、rubevy などで String や Array に書く使い方が出てきたら、気づきにくい。
