# rc2 との差を一度に洗い出す（調査だけ）

作成 2026-10-18。著者「作業するたびに気づいた点が見つかって収束できない」「気づいた点が出てくること自体は好ましいが、計画できないことが困っている」→ 全体を機械で一度洗い出して、有限の表にする（著者「push して洗い出しへ」）。**コードの直しはしない。** 結果を見て著者が直す線を決める。

正解は 4.1.0-rc2（Docker `kishima/mruby:4.1.0-rc2`、ソースは `/home/kishima/book/ref/mruby` の 4.1.0-rc2。**このクローンの HEAD を動かさない**。ほかの repo にファイルを作らない・消さない）。基準の SabiRuby は main の `f009316`。

## X1. メソッドの洗い出し

- 両方にあるクラスとメソッドの一覧を、両方の VM 自身から取る（`instance_methods(false)`、特異メソッド、Kernel）。片方にしか無いメソッドも表にする（rc2-leftovers9 の表の続き）。
- 受け手と引数の組を決めた表で呼ぶ: 引数 0〜3 個、値は nil・true・0・-1・1・2**70・1.5・NaN・Infinity・""・"abc"・"あ"・:sym・[]・[1,2]・{}・{a: 1}・1..3・proc・Struct のインスタンス・凍結した文字列・凍結した配列、キーワード引数 1 つ、block の有無。受け手はクラスごとに数種（空と中身あり、凍結）。組み合わせの数は先に数えて、走らせる時間から上限を決め、決め方を worklog に書く（根拠のない数を置かない）。
- 1 回の呼び出しごとに新しい受け手を作る（破壊的なメソッドの影響を次に持ち越さない）。止まる・外に出るメソッド（`exit`、`sleep`、`loop`、`Task` 系、`gets`、`system`、`require`、`eval` 系など）は外し、外した一覧を書く。1 回ごとに時間の上限。
- 比べるもの: 返り値の `inspect`（両方で同じ書き方で出す。ハッシュ値やアドレスのような作りで決まるものは、正規化の規則を決めて書く）、受け手のその後の `inspect`、例外のクラス、例外の文言。
- 分類: (v) 値が違う、(e) 例外のクラスが違う（片方だけ例外も含む）、(m) 文言だけ違う、(k) 既に記録した差（README Known deviations と backlog の「合わせない差」「著者が決めた本家との差」に当たるもの。当て方の規則を書く）。

## X2. Ruby のプログラムの洗い出し

- 本の `book_mruby3/data/code/*.rb`、sabiruby の `tests/custom/*.rb`、`mruby-porting-kit` のフィクスチャ（あれば）、本家 `test/t` と同梱 gem の `test/*.rb` の assert を 1 つずつ切り出したもの（edge-spec の道具で切り出せるならそれを使う）を、両方で走らせて標準出力・標準エラー・終了コードを比べる。
- 差が出たものは最小の再現に縮め、X1 と同じ分類。X1 と同じ原因のものはまとめる（原因ごとに 1 行）。

## 守ること

- ベンチを回さない（ほかの作業と並ぶため）。Docker の負荷が大きいときは並列の数を下げる。
